# 기획: 리스닝 빙고 — 원어민 음성 단어 빙고 (1~4인)

> 작성: 2026-08-10 · 상태: 기획 (미구현) · 배경: [effectiveness-audit-2026-08.md](effectiveness-audit-2026-08.md) 4차
> 요구: "최대 2~4인 영어학습 게임 추가 추천" (2026-08-10 사용자)

**한 줄**: 원어민 음성(또는 TTS)으로 단어를 불러주면, 각자 4x4 보드에서 그 단어를
찾아 탭 — 먼저 한 줄을 만들면 승리. 듣고 인지(recognition)가 전부인 첫 멀티게임.

## 왜 이 게임인가 — 후보 비교

| 후보 | 초급 접근성 | 빈 축 커버 | 구현 비용 | 판정 |
|---|---|---|---|---|
| **리스닝 빙고** | **높음** (타이핑·속도 압박 없음, 운 요소가 실력차 완충) | 리스닝 인지 + 음성 자산 활용 + (P2) 협동 | 중 — 기존 인프라 5종 재사용 | **추천** |
| 문장 릴레이 (협동 어순 조립) | 중 (어순은 중급+) | 협동 | 중 | P2 후보로 보류 |
| 협동 타워 디펜스 (공용 보드 실시간) | 낮음 | 협동 | 높음 (공유 보드 동기화) | 기각 — 비용 대비 검증 가치 낮음 |

추천 근거 (감사 4차의 구멍과 1:1):

1. **초급 무방비 대응** — 기존 멀티게임은 전부 속도·타이핑·어순 압박(중급+).
   빙고는 듣고 탭 하나라 study_level 1~2 사용자의 첫 멀티게임이 된다.
   보드 배치 운이 실력차를 완충해 **초보가 친구를 이길 수 있다** (지속 동기).
2. **음성 자산 회수** — 이 앱의 결정적 차별점(단어 정렬 원어민 발화 구간,
   word-alignment.md)이 게임에서는 받아쓰기(고급향)에만 쓰인다. 빙고는 아하
   모먼트("배운 단어를 원어민 발화로 듣는")를 멀티플레이로 확장한다.
3. **리스닝 근육** — 기존 게임은 전부 텍스트 인지. 소리→의미 매핑 게임은 0개.
4. **복습 편입 기본 탑재** — P0-A 인프라(우선 풀·ReviewPanel)를 처음부터 쓴다.

## 규칙 (MVP)

- **인원**: 1인(연습 — 빙고 없이 16문항 정답률 기록) / 2~4인(방 코드·친구 초대)
- **보드**: 참가자 공통 단어 16개 — **전원 같은 단어, 배치만 다름**(시드 개인화).
  단어는 참가자 due·최근 오답 우선(`priority_item_ids` 합집합 — P0-A 규칙 공유)
- **라운드** (16회, 호출 소진형):
  1. 서버가 다음 단어 지정 → 클라이언트가 **음성만 재생** (원어민 구간
     `media{video_id,start_ms,end_ms}` 우선, 없으면 `/tts` 신경망 TTS 폴백).
     텍스트·뜻은 보여주지 않는다 — 듣고 인지가 학습 본체
  2. 10초 안에 자기 보드에서 그 단어 탭 — 정답: 칸 채움 / 오답 탭: 1초 잠금
     (난사 방지) / 미탭: 그 칸은 영구 구멍 (자연 패널티, 재호출 없음)
  3. 라운드 끝에 단어+뜻 1.5초 공개 (받아쓰기 reveal 패턴 — 학습 모먼트)
- **승부**: 첫 **빙고 1줄**(가로/세로/대각) 달성자 승리. 16호출 소진 시 채운 칸
  수 → 오답 수 순. 속도 보너스 없음 — 로드 시간 차가 승부를 가르지 않게
- **복습 회수**: 내가 놓친(미탭·오답) 단어를 종료 시 `*.review` 개인 메시지로 →
  ReviewPanel 원탭 학습 추가 (전 게임 공통 패턴)

## 협동 모드 (P2 — 협동 축 신설, DAU 조건 없이 방 옵션으로)

"팀 빙고": 제한 시간 안에 **전원이 각자 1줄 이상** 만들면 팀 승리, 남은 시간이
팀 점수. 잘하는 친구가 끝나도 못하는 친구를 기다려야 해서(양성 상호의존)
"도와주는 대화"가 생긴다 — 기존 6게임에 없는 관계 동기.

## 구현 스케치 — 기존 인프라 재사용이 본체

| 필요 | 재사용 |
|---|---|
| 방/초대/재접속 | `typing_race.py` 매니저 구조 복제 (방 코드·초대·이탈 처리 검증됨) |
| 단어 풀 + 복습 우선 | `select_word_pool` + `safe_priority_items` (P0-A) |
| 음성 재생 | 문항 `media` 구간 → `SegmentPlayer` / `/tts?text=` 폴백 (임베드 규정 준수) |
| 오답 회수 | `review_items` + `ReviewPanel` |
| 기록/리더보드 | `*_races` 테이블 패턴 (`bingo_matches`) + 주간 리더보드 편입 |
| 테마 | 보드 칸은 `SURFACE_SKINS` 선지 스킨 재사용 (theme-addition 체크리스트 적용) |

신규 작성분: 빙고 룰 매니저 1개(서버) + 게임 페이지 1개(클라). 신규 표면은 게임
허브 카드 1장 — 학습 탭 인지 부하(감사 경고)와 무관.

주의: 원어민 구간이 없는 단어가 많은 풀이면 TTS 위주가 된다 — 보드 선정 시
**media 보유 단어 우선** 가중(아하 모먼트 정렬과 동일 원칙)을 함께 넣는다.

## PM 판정 (cg-pm 3문)

| 질문 | 점수 | 근거 |
|---|---|---|
| Q1. Why now? | 3 | 4차 실측 — 게임이 산 표면(주 17판), 초급 무방비·리스닝/협동 축 공백 확인 |
| Q2. Who suffers if not? | 2 | 초급 사용자가 즐길 멀티게임 0 → 3일차 이탈 시나리오 지속. 정렬 파이프라인 투자가 게임에서 미회수 |
| Q3. Smallest slice? | 3 | 신규 코드 2파일 + 인프라 5종 재사용. 협동 모드는 P2 분리 |

**Verdict: PM-PASS** — 단, 구현 착수는 P0-B(공급 시스템화)와 운영 실행(초급
콘텐츠 5편) 뒤로. **초급 단어가 0인 상태에서는 초급용 게임도 소재가 없다** —
공급이 먼저다.

## 성공 지표

- 신규(첫 주) 사용자의 빙고 참여율 — 초급 진입 게임 가설 검증
- 판당 놓친 단어 → 카드 담기 전환율 (복습 회수 루프)
- 원어민 구간 재생 비율 (TTS 폴백 비율이 높으면 정렬 커버리지 문제 신호)
- 협동 모드(P2): 팀 승리 후 재대결율
