# 기획: 발음 채점 (Pronunciation Scoring) — 필요성 평가와 단계 설계

> 작성 2026-08-21 · 상태: **기획 (구현 전)** · 발단: cake-benchmark 마무리에서
> "Cake 의 콘텐츠 측 장점 중 미소화 항목"으로 식별, 사용자 요청으로 타당성 평가

## 0. 한 줄 결론

**필요하다 — 단, 정밀 채점부터가 아니라 "통과/재시도" 게이트부터.** 한국
시장의 최대 획득 동력이 "말하기"임은 유사 서비스가 증명했고, 우리 앱은 이미
녹음-비교(RecordCompare)까지 와 있어 채점은 신규 기능이 아니라 **기존 아웃풋
고리의 피드백 완성**이다.

## 1. 유사 서비스 근거 — 왜 필요한가

### 1.1 유저 확보 관점

| 서비스 | 규모 | 채점 방식 | 시사점 |
|---|---|---|---|
| **ELSA Speak** | 9,000만+ 다운로드 (2026-01), 2,500만+ 사용자 | 음소 단위 정밀 채점 (정확도·강세·억양), IELTS 예측 | **발음 채점 단일 기능만으로 카테고리 리더** — 수요 자체가 거대 |
| **스픽 (Speak)** | 유니콘 (기업가치 1.4조, 2024-12), 다운로드의 약 60%가 한국 (한국 550만) | AI 음성인식 — "다른 앱보다 5~10배 더 말하게" | **한국 사용자는 '말하기'에 지갑을 연다** — 우리 타깃 시장의 1순위 수요 |
| Cake | 수천만 다운로드 | 문장 따라 말하기 + AI 발음 평가 | 콘텐츠 앱도 스피킹 채점을 표준 장비로 탑재 |
| Duolingo | 5억+ | 말하기 문제 (인식 통과형) | 정밀 채점 없이 **인식 통과형만으로도** 스피킹 루프 성립 |

핵심 독해: 시장 1·2위 격인 ELSA·스픽의 공통분모는 "내 발음이 어떤지 **숫자로
알려준다**"이다. 우리 앱의 랜딩 서사(인풋→전환→아웃풋→증거)에서 아웃풋의
'증거'가 현재 비어 있다 — 녹음-비교는 주관적 자가 판단에 머문다.

### 1.2 영어 실력 향상 관점

- **아웃풋 효과 (production effect)**: 소리 내어 산출한 항목이 눈으로만 본
  항목보다 기억에 오래 남는다 — 우리 FSRS 복습 루프와 직결.
- **CAPT (컴퓨터 발음 훈련) 연구**: ASR 기반 즉시 교정 피드백은 명료성
  (intelligibility)을 유의하게 개선 — 피드백 없는 따라 말하기(현행)보다
  효과가 크다. ELSA 는 "앱 27시간 = 미국 대학 ESL 스피킹 코스" 를 마케팅
  근거로 사용.
- **행동 유발**: 점수는 재시도를 만든다. 현행 RecordCompare 는 1회 듣고
  넘어가지만, "83점 → 한 번 더?" 는 반복 발화를 만든다 (스픽의 5~10배
  발화량 주장과 같은 메커니즘).

## 2. 우리 앱 현황 — 이미 있는 것

| 자산 | 위치 | 채점에 재사용 |
|---|---|---|
| 녹음-비교 (서버 무저장) | `components/media/RecordCompare.tsx` (MediaRecorder) | 마이크 UX·권한 흐름 그대로, 채점만 부착 |
| 따라 말하기 루틴 단계 | 정복 루틴 4단계 (content-routine.md) | 채점 게이트 부착 지점 |
| 원어민 구간 재생 + TTS | 라이브러리 플레이어·tts_audio | 목표 발화의 정답 음성 |
| 보상 체계 | 데일리 미션·XP·업적·주간 성적표 | "발음 90점 미션" 등 즉시 결합 |
| 약점 추적 패턴 | word-insight (오답 단어 인사이트) | 약점 음소 추적으로 확장 |

## 3. 단계 설계 (사다리 — 싼 것부터)

### V1 — 인식 통과형 (무료, 브라우저 STT) · P1

Duolingo 방식. **Web Speech API**(브라우저 내장 음성인식)로 발화를 텍스트로
받고, 목표 문장과 단어 일치율로 3등급 판정: `완벽(90%+) / 좋아요(70%+) /
다시 한번`.

- 부착 지점: ① RecordCompare 에 "인식 확인" 버튼 ② 정복 루틴 4단계 완료
  조건(등급 무관, 시도만으로 통과 — 좌절 방지) ③ 데일리 미션 풀에
  "따라 말하기 3문장" 추가
- 비용 0 (브라우저 내장) · 서버 전송 없음 → 현행 프라이버시 원칙(서버
  무저장) 유지
- 제약: iOS Safari 는 `webkitSpeechRecognition` 지원이 불안정 — **미지원
  기기는 현행 녹음-비교로 자동 폴백** (기능 게이트, VAPID 미설정 숨김 선례)

### V2 — 정밀 채점 (Azure Pronunciation Assessment) · V1 사용률 검증 후

음소·단어별 정확도 + 유창성·완결성·운율 점수. ELSA 급 피드백.

- 문장 카드에 단어별 색 히트맵 (초록=정확, 빨강=교정 필요), 약점 음소
  주간 리포트 (word-insight 패턴)
- 비용: 종량제 (오디오 시간당 과금) — 문장당 3~5초라 1인 하루 20문장
  기준 월 수백 원 수준. 무료 사용자 일일 상한 필요
- **프라이버시 전환점**: 음성이 외부 API 로 전송된다 — 최초 1회 고지·동의
  UI 필수 (현행 "서버 저장 없음" 원칙의 명시적 예외라 스펙에 못박을 것)

### V3 — 검토만 (백로그)

발음 대전 게임(점수 경쟁), 주간 성적표에 발음 지표 편입. V2 정착 후.

## 4. 성공 지표

- V1: 스피킹 시도율 (세션당 인식 확인 클릭), 루틴 4단계 완료율 변화,
  재시도율 ("다시 한번" 후 재발화 비율)
- 리텐션: 스피킹 사용자 vs 비사용자 D7/D30 (usage_events 로 측정 가능)

## 5. 리스크

| 리스크 | 대응 |
|---|---|
| iOS 인식 미지원/오탐 | 기기 게이트 + 녹음-비교 폴백, 등급이 아닌 시도 기준 통과 |
| 소음 환경 오탐 → 좌절 | "다시 한번" 은 감점·차단 없음, 3회 시도 시 자동 통과 |
