# 기획: 스피드 퀴즈 로얄 — 최대 4인 버저 퀴즈

> 작성: 2026-07-14 · 상태: 승인됨 (사용자 goal: 영어 학습용 최대 4명 참가 네트워크 게임)
> 벤치마크: Kahoot!(동시 출제+속도 점수), 워드 테트리스 인프라 재사용

## 한 줄 요약

같은 4지선다 문제를 **최대 4명에게 동시 출제**하고, 빨르고 정확하게 답할수록
높은 점수를 주는 라운드제 퀴즈 대전. 문제는 내 학습 풀(선다 퀴즈·유사단어
오답 선지)에서 나온다.

## 왜 이 게임인가 (테트리스 대비)

1. **서버가 가볍다**: 실시간 낙하 tick 없음 — 라운드 이벤트 기반이라 2GB
   서버에서 4인 방 다수 수용 가능
2. **학습 파이프라인과 직결**: 기존 `quiz.build_question`(유사단어 오답
   선지 포함)을 그대로 사용 — 게임이 곧 복습
3. **4인 확장이 자연스러움**: 테트리스는 보드 4개 렌더가 부담,
   퀴즈는 참가자 수와 무관하게 화면 1장
4. **기존 UX 재사용**: 방 코드 초대, 소재(내 콘텐츠) 선택, WS 연결 그대로

## 게임 규칙

| 항목 | 값 |
|---|---|
| 인원 | 2~4인 (방 코드) 또는 1인+봇 1~3 (AI 대전) |
| 라운드 | 10개, 문제당 제한 10초 |
| 문제 | 4지선다 (영→한 / 한→영 랜덤, 유사단어 오답 선지) |
| 제출 | 1인 1회, 수정 불가 |
| 점수 | 정답 = 50 + ⌈50 × 남은시간/제한시간⌉ (최대 100), 오답/미제출 = 0 |
| 라운드 종료 | 전원 제출 또는 시간 만료 → 정답·획득 점수·누적 순위 3초 공개 |
| 승자 | 10라운드 합산 1위 (동점은 공동 순위) |

## 진행 흐름

```
로비(모드 선택) → 대기실(방 코드 공유, 호스트 시작) →
라운드 x10 [출제 → 각자 답 → 공개] → 시상대(순위) → 다시 하기
```

## 기술 설계

- **세션**: `services/game/quiz_royale.py` — 테트리스 매니저와 분리된
  독립 세션 (라운드 상태 + asyncio 태스크 1개/방). 단어 풀은
  `select_word_pool` 공유
- **봇**: 레벨 1~5, 정답 확률 `0.35+0.1×레벨`, 응답 시간 정규분포 —
  혼자서도 플레이 가능 (리텐션)
- **WS 프로토콜** (기존 `/ws/game` 라우터에 `qr.*` 타입 추가):
  - C→S: `qr.solo{level,bots}`, `qr.create{content_ids?}`, `qr.join{code}`,
    `qr.start`, `qr.answer{round,answer}`, `qr.leave`
  - S→C: `qr.room{code,players,host}`, `qr.round{no,total,prompt,choices,seconds}`,
    `qr.answered{name}`, `qr.reveal{answer,gains,scores}`, `qr.end{ranking}`
- **저장**: `quiz_royale_matches(id, host_id, mode, status, players JSONB, ended_at)`
  — 1:1 전용인 game_matches 와 분리. 리더보드 합산은 P2
- **프론트**: `/game` 로비에 모드 섹션 추가 + `QuizRoyale.tsx`
  (대기실/라운드/공개/시상대 4상태), 선지 버튼은 학습 선다 UI 재사용

## 단계

| 단계 | 범위 |
|---|---|
| P1 (이번) | 2~4인 방 + 봇 채움 솔로, 10라운드, 점수/시상대, 매치 저장 |
| P2 | 리더보드 합산, 관전, 라운드 수/시간 설정, 오답 → 원탭 학습 추가 |

## 결정 사항

- 테트리스와 대기열 미공유 — 퀴즈는 방/솔로만 (빠른대전 매칭은 인원 모이면 P2)
- 문제 풀은 방장(호스트/솔로 본인)의 가시성 기준 (테트리스 소재 선택과 동일 규칙)
- 중도 이탈자는 미제출 0점 처리로 계속 진행, 1인만 남으면 조기 종료
