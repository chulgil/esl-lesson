# 기획: XP 상점 확장 — 마스코트·악세사리 (벤치마크 조사 포함)

> 작성: 2026-08-11 · 상태: **구현 완료 (2026-08-11)** — 정본: [specs/mascot-shop.md](../specs/mascot-shop.md)
> 요구: "XP 로 살 수 있는 게 없다. 캐릭터를 팔아 화면에 배치하고, 복수 캐릭터 +
> 옷/악세(사면 전부 착용)로. 동작이 어색하지 않게 여러 번 검증. 타 서비스 전수조사" (2026-08-11 사용자)

## 문제 진단

- XP 상점(테마 구매)은 2026-08-05 에 완성됐지만 **프로드에 가격이 하나도 입력되지
  않아**(theme_settings 0행, xp_spends 0행) 사용자에겐 "살 것이 없는" 상태였다 —
  장치 문제가 아니라 운영 미실행. 코드 시드로 전환해 재발을 막는다.
- 헤냥이는 cat 테마 전용 + cat 은 초기 2계정 전용 지급이라 사실상 아무도 못 봤다
  ("우하단에 있다가 사라졌다"는 체감의 실체 — 실제로는 좌하단 이동 + 노출 조건 협소).

## 벤치마크 조사 (2026-08-11 — Duolingo/Habitica/Forest/Memrise/콴다·열품타)

| 서비스 | 루프 | 시사점 |
|---|---|---|
| Duolingo | 젬(일퀘 15~45) → 스트릭 프리즈 200·복장 → 하단 탭 상점 상시 | 복장 폐지(2022)에 유저 반발 — **캐릭터 애착 장치는 유지가 정답** |
| Habitica | 골드 → 장비/펫, 아바타가 모든 화면 헤더 상시 | 꾸민 결과의 **상시 노출**이 핵심 |
| Forest | 코인(25분≈8~10) → 수종 수백~2000+ | 홈 자체가 수집 결과물(숲) — 수집 도감형 장기 리텐션 |
| 콴다·열품타 | 기능성 화폐(질문권)·타이머 테마 꾸미기 | 꾸미기는 유저 자발 문화가 됨 |

공통 패턴: ① 소모품 가격 = 4~10일치 획득량, 프리미엄은 층위 상단 ② 꾸미기는
매일 보는 화면에 상시 노출 ③ 수집 완성 욕구 ④ 손실 방어 아이템(스트릭 프리즈)이
최고 인기.

## 결정

| 결정 | 내용 |
|---|---|
| 테마 가격 코드 시드 | 운영 약속 대신 마이그레이션이 기본 가격 입력 (백오피스 기입분은 보존) — 공급 위젯(P0-B)과 같은 "약속→시스템" 원칙 |
| 마스코트 3종 + 악세 4종 | 헤냥이 2000 / 브리키·몽이 1500, 리본 300~왕관 1000 — 일일 ~500XP 기준 1~4일치 |
| 좌하단 상시 노출 | 슬롯 규정(우하단=채팅 런처) 준수 — "적절한 위치" = 좌하단. 구매 즉시 자동 활성 |
| 악세 all-on | 착용 토글 없음 — 보유하면 전부 착용 (사용자 결정: 심플) |
| 책갈피 XP 충전 | 벤치마크 1순위(손실 회피) 상품 — 500XP, 최대 2 유지 |
| 검증 픽스처 | `/design/mascots` — 조합·반전·애니메이션을 반복 검증하는 상설 QA 화면 |

기각: 착용 토글/슬롯별 장착(복잡도 대비 가치 낮음 — all-on 결정), 마스코트별
전용 악세(앵커만 캐릭터별로 조정, 카탈로그는 공용).

## 검증 기록 (2026-08-11 — "여러 번" 요구 이행)

1차: 전 조합 스크린샷 → **말풍선 글자 반전 발견** (구 헤냥이도 동일 버그) → flip 역반전 도입
2차: 수정 확인 → 헤냥이 글자 의심 → 확대 검증으로 폰트 렌더 정상 판정
3차: 확대 검증 → **브리키·몽이 목도리가 입을 가림, 브리키 리본 부유** → 앵커 보정
4차: 보정 확인 — 전 조합 자연스러움 합격
동작: idle 3종(giggle/bounce/float) 시간차 좌표 측정으로 작동 확인 (6샘플 전원 상이)

## 성공 지표

- xp_spends 발생 수(현재 0) — 상점 작동의 직접 증거
- 마스코트 활성 사용자 수 / 악세 보유 분포 (item_grants)
- 구매 후 7일 잔존 vs 미구매 (애착 장치 가설)
