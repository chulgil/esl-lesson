# 기획 검증: 이 학습 방식은 정말 효과가 있고, 계속하게 되는가

> 작성: 2026-08-05 · 상태: 검증 완료, 보완 P0 착수
> 방법: 기획자(냉정한 심사) + 사용자 페르소나 3인 저니 워크스루 + 프로드 실측
> 실측(2026-08-05): 공용 콘텐츠 10개 · 학습 항목 847개(중급 592 / 고급 255 /
> **초급 0**) · 사용자 4명

## 한 줄 결론

**중급 학습자가 2주 쓰는 앱으로는 이미 잘 설계됐다. 그러나 "계속하게" 만드는
세 기둥 — 콘텐츠 공급 리듬, 난이도 사다리, 효과의 체감 증거 — 이 비어 있어
3주차 이후와 초급 사용자에서 무너진다.** 기능 추가가 아니라 이 세 기둥을 메운다.

## 효과성 검증 — 인과 사슬 점검

"영어가 는다"의 사슬: 인풋 → 전환(연습) → 아웃풋 → 증거(체감) → 재투자

| 고리 | 현재 장치 | 판정 |
|---|---|---|
| 인풋 | 실전 유튜브 문맥 + FSRS 간격 반복 + 원어민 음성 연계 + 신경망 발음 | **강함** — 과학적 근거 확실 (간격 반복·실제 문맥 학습은 문헌상 최상위 효과) |
| 전환 | 오답 정리·힌트 숙련도 분기·루틴 6단계·섀도잉 | 보통 — 장치는 갖췄으나 도입 직후라 사용률 미관측 |
| 아웃풋 | 레벨 4 타이핑(고급만) + 한 문장 요약 | **약함** — 말하기 0. "입이 트인다"는 체감의 최대 원천이 루프에 없다 |
| 증거 | 장기 기억 지표·XP·업적 | 보통 — 전부 **내부 지표**. 사용자가 믿는 준거는 "안 들리던 영상이 들린다"인데 이를 측정·상기하는 장치가 없다 |

## 지속 의지 검증 — 세 기둥의 구멍

### 구멍 1. 콘텐츠 공급 리듬이 없다 (치명)

공용 콘텐츠 10개. 열심히 하는 사용자는 **2~3주면 소진**한다. 등록은 관리자
수동이고 공급 주기 약속이 없다 — 구독 서비스로 치면 "다음 화 없는 드라마".
개인 등록(하루 10건)이 있지만 일반 사용자 동선에서 보이지 않는다.

### 구멍 2. 난이도 사다리가 없다 (치명 — 실측으로 확정)

항목 847개 중 **초급 0개**. TED 류는 원전 루틴의 전제(60~80% 이해)를 초급에게
충족하지 못한다 — 초급 사용자에게 "실전 콘텐츠" 차별점은 그대로 좌절 요인이
된다. 학습 난이도(study_level)는 퀴즈 형식만 바꿀 뿐 콘텐츠 난이도를 못 바꾸고,
라이브러리에는 난이도 표시조차 없어 "내가 담아도 되는 영상인지"를 알 수 없다.

### 구멍 3. 아하 모먼트가 우연에 맡겨져 있다

이 앱의 결정적 순간은 **"방금 배운 그 단어를, 그 영상의 원어민 발화로 듣는"**
경험이다. 그런데 신규 사용자의 첫 세션에서 음성 연계(media) 있는 카드가 나올지는
정렬 운에 달렸다 — 첫 20문항이 전부 텍스트 카드면 듀오링고와 다를 게 없어 보인다.

### 경고. 인지 부하 — 기능이 계약을 가리기 시작

학습 탭에만 오답 정리·덱·시험·컬렉션·장기 기억·어휘망·친구·랭킹·업적이 쌓였다.
"오늘 뭘 얼마나 하면 끝인지"의 계약이 흐려지면 장치가 많을수록 부담이 된다.
당분간 **신규 표면 동결** — 새 장치는 기존 표면 교체로만.

## 보완 기획

### P0-1. 첫 세션 아하 모먼트 보장 (이번 구현)

신규 카드 도입 정렬에서 **같은 레벨 안에서는 음성 연계(media) 있는 항목 우선**.
첫 세션 20문항에 "듣는 카드"가 반드시 섞이도록 — 차별점을 운이 아니라 설계로.

### P0-2. 콘텐츠 난이도 배지 + 이해 예상 (구현 완료 2026-08-05)

- 등록 시 콘텐츠 난이도 산출: 항목 difficulty_hint 분포 + 문장 길이로
  초급/중급/고급 자동 라벨 (백오피스에서 수정 가능)
- 라이브러리 카드에 난이도 배지 + "내 수준과의 거리" (내 카드와 겹치는 항목
  비율로 이해 예상 % — ted-routine P2 항목 격상)

구현분: `GET /api/contents` 가 `difficulty`(항목 분포 가중 평균)·`known_ratio`(내
카드 보유 비율)를 실시간 파생하고, 라이브러리 카드가 난이도 배지와 "아는 표현 n%"
칩을 보여준다 (산출 규칙: specs/content-governance.md). 저장 컬럼이 없으므로 **문장
길이 가중과 백오피스 수동 수정은 미구현** — 필요해지면 컬럼 추가 후 착수한다.

### P0-3. 콘텐츠 공급 운영 리듬 (운영 결정 — 코드 아님)

- **주 2편 등록을 운영 약속으로** (요일 고정 — 새 출발 효과와 결합해 월·목 등)
- 초급 트랙 신설: CC 검색에 초급 채널 키워드 가이드(easy english, learn english
  slowly, kids story 등)로 **초급 콘텐츠 5편 우선 확보** — 초급 0 상태 해소
- 사용자 요청 경로: 라이브러리 빈 상태·바닥에 "이런 영상이 보고 싶어요" 요청
  폼(P1) — 공급을 수요와 연결

### P1. 효과의 체감 증거 — 재청취 이해도 (구현 완료 2026-08-05)

루틴 1단계(첫 청취)와 6단계(요약) 시점에 **"얼마나 들렸나요?" 1~5 셀프 체크**를
끼운다. 같은 영상의 전후 비교 + 콘텐츠 누적 그래프 = "안 들리던 게 들린다"의
측정 가능한 증거. 주간 성적표(benchmark P2)의 핵심 재료가 된다.

> 전후 비교까지 구현 — 스펙: [content-routine.md](../specs/content-routine.md) §재청취 이해도.
> 콘텐츠 누적 그래프는 주간 성적표(P2)와 함께.

### P2 (기존 로드맵 유지 + 격상 1건)

- **말하기 녹음 비교를 P2 최우선으로 격상** (ted-routine P2) — 아웃풋 고리의
  최대 구멍. 이후 STT 발음 피드백 검토
- 주간 성적표·배치고사·친구 협동 목표: 기존 로드맵 유지 (DAU 조건부)

## 2차 검증 라운드 (2026-08-06)

1차 보완 배포 다음 날 실측: 루틴 진행·이해도 체크·요약 **사용 0건**, 콘텐츠
여전히 10개. 진단 — 장치는 충분한데 ① 데일리 동선(홈->세션)에서 루틴이 안
보이고 ② 아웃풋(말하기)이 비었고 ③ 공급이 수요와 안 닿는다. 보완 3종 구현:

| 보완 | 내용 |
|---|---|
| 발견 가능성 | 학습 탭 덱마다 "갈아 넣기 n/6" 진행 브릭 + 상세 링크 (`decks.routine_done`) — 시작한 여정을 매일 상기 |
| 아웃풋 (P2 격상분) | 말하기 녹음 즉석 비교 — 현재 문장을 따라 말해 녹음하고 내 발음 vs 원어민 교차 재생 (MediaRecorder, 서버 저장 없음) |
| 공급-수요 연결 | 라이브러리 "이런 영상이 보고 싶어요" 요청 폼(하루 5건) -> 백오피스 등록 화면 CC 검색 옆에 요청 목록 노출 |

여전히 운영 대기: 주 2편 등록 약속 + 초급 5편 확보 (코드로 해결 불가).
다음 관측점: 루틴·이해도 사용률이 여전히 0 이면 온보딩에 루틴 안내 삽입 검토.

## 3차 검증 라운드 (2026-08-06 — 2차 직후 기획 재감사)

1·2차가 **장치**(무엇을 만들까)와 **발견 가능성**(어디에 둘까)을 다뤘다면, 3차는
**신념과 증거의 루프**를 본다 — 사용자가 ① 방법을 믿고 시작해서 ② 주 단위
증거를 받아 재투자하는 구조가 있는가.

### 재검증 통과 (이상 없음 확인)

- **최소 행동 바닥**: 스트릭은 "복습 1개 이상"이면 유지(`streak_with_savers` —
  daily>0 판정) — 바쁜 날 1분 학습으로 습관이 안 끊긴다. 다만 이 사실을
  사용자에게 말하는 곳이 없다 → 주간 성적표 카피에 흡수 (구멍 5).
- 피크엔드·복귀 감사·아하 모먼트 정렬·힌트 숙련도 분기: 1·2차 보완대로 배치 확인.

### 구멍 4. 방법을 가르치지 않는다 (P0 — 신념 기둥)

비로그인 랜딩은 방법을 설명하는데("망각곡선이 계산해…"), **로그인 후에는 어디에도
"이 앱으로 어떻게 공부하면 느는가"가 없다**. 갈아 넣기 6단계(이 앱의 교수법
본체)는 라이브러리 상세까지 들어가야 처음 만나고, 온보딩 체크리스트는 2항목(첫
학습·친구 추가)뿐 — 친구 추가는 학습 핵심이 아니다. 2차 "사용 0건"의 근본 원인
후보는 발견 가능성(2차 보완)만이 아니라 **의미 이해 부재** — 왜 하는지 모르는
장치는 보여도 안 쓴다.

보완 — 첫 주 계약 (구현 완료 2026-08-07 — 스펙: [ui-design.md](../specs/ui-design.md) "첫 주 계약"):

1. **온보딩 체크리스트를 학습 핵심 3단계로 재구성** — ① 첫 학습 ② 첫 영상
   갈아 넣기 시작(루틴 1단계 체크) ③ 리마인더 시각 설정(실행 의도 —
   user-journey P1 잔여 흡수). 친구 추가는 3단계 완료 후에만 노출.
2. **"이 앱이 영어를 늘리는 방법" 1화면** — 인풋(진짜 발화) → 전환(매일 복습) →
   아웃풋(섀도잉·요약·녹음) → 증거(재청취 체크) 4고리 요약 + 첫 주 기대치
   ("첫 주엔 하루 15개 + 영상 1편이면 충분"). 온보딩 체크리스트와 라이브러리
   빈 상태에서 링크. 랜딩 카피 재사용 — 신규 서사 창작 금지 (표면 동결 원칙:
   기존 온보딩 표면의 교체이지 신규 표면 아님).

### 구멍 5. 증거가 쌓이는데 주 단위로 돌려주지 않는다 (주간 성적표 P1 격상)

재료는 이미 전부 있다(장기 기억 델타·재청취 전후·루틴 진행·정답률·스트릭). 그런데
세 문서(retention·benchmark·journey)가 모두 주간 성적표를 P2로 미뤄왔다 — **증거
기둥의 집계 장치가 계속 비어 있다.** 효과의 체감이 일 단위(세션 완료 화면)엔
있는데 주 단위 서사("이번 주의 나 vs 지난주의 나")가 없어, 7일차 이탈 시나리오
("이게 느는 건가")의 대응이 여전히 부분에 머문다.

스펙 방향 (구현 시 specs/weekly-report.md 로 이동):

- **산출**: 월요일 KST 기준 지난주 요약 — 복습 수(전주 대비 델타)·정답률·장기
  기억 +N·루틴 단계 진행·재청취 델타(있으면 강조). 전부 기존 로그 실시간
  파생 — 스냅샷 테이블 없음 (장기 기억 지표와 동일 원칙).
- **노출**: 월요일 푸시(새 출발 효과, `reminder_hour` 존중) + 홈 배너 1회
  (복귀 감사 배너와 동일 패턴) + 학습 탭 카드.
- **카피**: 절대치가 아니라 델타 중심("지난주보다 +12") + 다음 주 한 줄 제안
  1개. "1개만 해도 스트릭은 이어져요" (최소 행동 바닥 고지) 포함.

### 재확인 — 여전히 코드 밖 (운영, 3차에서도 최우선)

주 2편 등록 약속·초급 5편 확보는 1차(08-05) 이후 미이행. **공용 콘텐츠가 10개로
남아 있는 한 구멍 4·5를 포함한 모든 장치가 3주차에 무효가 된다** — 이번 주 내
실행을 다시 권고한다.

### 다음 관측점 (3~5일 후, 4차)

- 루틴 진행 브릭(2차)이 사용률 0을 깼는지 — 구멍 4 보완 효과와 분리 측정 위해
  구멍 4 배포 전후 구간을 나눠 본다
- 말하기 녹음 사용 여부 · 콘텐츠 요청 유입 수 · 신규 가입자의 온보딩 3단계 완료율

## 강점 재확인 (지킬 것)
