# 스펙: 대화방 공지 — 자유 텍스트 목표·약속 고정 (2026-08-13)

> 기획 의도: 함께 목표(shared-goals.md)는 구조화된 두 가지(자동 주간 달성표 +
> 한 줄 체크리스트)뿐이라 서술형 목표("8월엔 매일 30분", 스터디 규칙, 다짐)를
> 쓸 곳이 없다 (2026-08-13 사용자 보고 — "목표만 있어서 커스터마이징이 안 된다").
> 카톡 공지처럼 **대화방 설정에서 적으면 상단에 뜨는, 평소엔 숨겨진** 자유
> 텍스트 공지를 추가한다.

## 결정 (2026-08-13 인터뷰)

| 항목 | 결정 |
|---|---|
| 형태 | 목표 보드와 **별도**의 대화방 고정 공지 — 목표 외 용도(약속·알림)도 허용 |
| 개수 | 대화당 1개 — 새로 쓰면 교체 (카톡 모델) |
| 편집 | 두 참가자 모두 수정·해제 가능 (함께 목표와 같은 공동 편집) |
| 노출 | **기본 숨김** — 공지가 있을 때만 헤더 아래·함께 목표 바 위에 접이식 바 |
| 변경 인지 | 채팅 흐름 안 시스템 줄 ("OO님이 공지를 등록했어요") — 별도 푸시·벨 없음 |
| 진입점 | 대화방 헤더 케밥 메뉴(신설) → "공지 쓰기/수정/내리기" |
| 구조 | **제목 + 내용** (2026-08-13 사용자 지적 — "첫 줄 = 제목" 암묵 규칙은 알 수 없다). 접힌 바·시스템 줄 미리보기 = 제목 |
| 한도 | 제목 필수(한 줄, 80자 — 공백만/줄바꿈/초과 422), 내용 선택(500자, 줄바꿈 허용) |

기각: 목표 보드 내 메모 칸(사용자 선택으로 기각), 메시지 고정 방식(공동 편집
불가), conversations 컬럼 추가(대화방 스코프 공유 행 패턴이 이미 있음).

## 데이터 모델 (새 테이블 없음)

- **공지 본문**: `shared_goals` 에 `kind="notice"` 행 (대화당 1행 —
  `weekly_reviews` 패턴). `title`=제목(String(80), 마이그레이션 c6d7e8f9a0b1,
  2026-08-13), `text`=내용, `created_by`=마지막 편집자, `updated_at`=편집 시각.
  테이블명은 역사적 유산 — "대화방 스코프 공유 행" 범용 (shared-goals.md 참조)
- **시스템 줄**: `chat_messages.kind String(16) NULL` 컬럼 신설 (마이그레이션
  1건, NULL=일반 메시지). `kind="notice_set"`(등록·수정, body=**제목** 스냅샷)
  / `"notice_clear"`(내리기, body=""). sender=편집자,
  client_msg_id 는 서버 생성(uuid)

## API (참가자만 — 함께 목표와 동일 게이트)

| 메서드/경로 | 역할 |
|---|---|
| GET `/api/chat/with/{other_id}/notice` | `{text, updated_at, updated_by_name}` — 없으면 `{text: null}`. 대화 없으면 친구 검증 후 null (goals get_view 패턴) |
| PUT `/api/chat/with/{other_id}/notice` | `{title, text?}` upsert — invalid_title(공백만·줄바꿈)/title_too_long(80)/text_too_long(500) 422. 대화 없으면 친구 검증 후 생성. 응답·GET 은 `{title, text, updated_at, updated_by_name}` (없으면 title/text null). title 도입(2026-08-13) 전 레거시 행은 title null + text 만 — 조회 성립, 바 제목은 text 첫 줄 폴백 |
| DELETE `/api/chat/with/{other_id}/notice` | 공지 내리기 — 멱등 204 (없어도 204) |

- **친구 해제 후**: 조회는 유지, PUT/DELETE 는 403 `not_friends` — 공동 편집
  표면 공통 규칙 (shared-goals.md 2026-08-13 절과 동일)
- 변경 성공 시: (1) 시스템 줄 1행 적재 — 일반 메시지 파이프라인(WS 푸시·커서·
  `last_message_at` 갱신)을 그대로 탄다 (2) 양쪽에 WS
  `{"t":"chat.notice","conversation_id"}` 푸시 → 클라 공지 재조회 (goal.sync 패턴)

## 시스템 줄 제외 규칙 (파이프라인 오염 방지)

`kind IS NOT NULL` 행은 다음에서 제외한다:

- 자동 번역 (TranslationLine 미부착 — 프론트 렌더 분기)
- "내가 쓰는 말" 수집 (`my_phrases` 스캔에서 kind 행 스킵)
- OS 웹푸시 (오프라인 알림 발송 안 함 — 시스템 줄은 조용한 인지)
- 답글 인용(reply_to) 대상 아님

unread 배지·대화 목록 미리보기에는 일반 메시지처럼 포함 (특별 분기 없음 —
공지 변경도 대화 사건이다).

## 프론트 (3뷰 공통 — GoalBoard 와 동일 배치 원칙)

- **NoticeBar**: 헤더 아래·GoalBoard 위. 공지 없으면 렌더 안 함. 접힘=제목만
  ("[공지] **제목**"), 펼침=제목(굵게)+내용. **[수정]/[내리기]는 바 줄의 접기 토글([+]) 옆**
  (2026-08-13 사용자 피드백 — 펼쳐야 보이는 하단 배치는 못 찾는다). 접힘
  상태는 기기 로컬 기억 (localStorage `esl:chat-notice:fold:{otherId}`) — 기본 접힘
- **헤더 케밥 메뉴 신설**: "공지 쓰기"(있으면 "공지 수정") → 제목 입력(80자)
  + 내용 textarea(500자 카운터) 시트. "함께 목표" 항목도 여기서 진입 (shared-goals.md 2026-08-13
  기본 숨김 전환) — 대화방 설정 항목의 공용 진입점
- **시스템 줄**: 중앙 정렬 회색 한 줄 — `notice_set` → "OO님이 공지를
  등록했어요: {첫줄}", `notice_clear` → "OO님이 공지를 내렸어요". 말풍선 아님.
  **편집자 본인 화면에도 즉시 표시** — 일반 내 글은 HTTP 응답으로 붙지만
  시스템 줄은 WS 가 유일 경로라, 클라 수신 필터가 kind 행은 발신자 무관하게
  붙인다 (2026-08-13 픽스: 본인 수정 시 줄이 안 뜨던 문제)
- **위장(excel)**: "공지"는 업무 앱에도 자연스러운 어휘 — 라벨 유지, 플레인
  바(말풍선·캐릭터 금지 계약 유지). 유니코드 이모지 금지
- WS `chat.notice` 수신 시 공지 재조회, `chat.new` 의 kind 행은 시스템 줄 렌더

## 테스트 계약 (성공 기준)

- PUT → GET 반영, 재 PUT 교체(1행 유지), DELETE 멱등 204 → GET null
- 422: 제목 공백만·줄바꿈·80자 초과, 내용 500자 초과 / 404: 비친구+대화 없음 / 403: 친구 해제 후 PUT·DELETE
- 시스템 줄: PUT 시 `kind="notice_set"` 행 적재 + 양쪽 WS 푸시,
  my-phrases 동기화가 kind 행을 수집하지 않음
- 프론트: 공지 없으면 바 미렌더, 등록 후 표시, tsc·lint 통과

## 공지 체크리스트 (2026-08-21 설계 — 구현 전)

> 요청: "공지사항에 체크리스트도 등록할 수 있도록". 함께 목표의 한 줄
> 체크리스트는 '목표' 스코프라, 공지의 용도(스터디 규칙·과제·준비물)에 맞는
> 항목별 체크가 없었다.

### 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 문법 | 내용(500자) 안에서 `[] 항목` 으로 시작하는 줄 = 체크 항목 (`[x]` = 완료) | 새 테이블·새 편집 UI 없이 기존 제목+내용 모델 위에 얹는다 (simplicity ladder 2번) |
| 렌더 | NoticeBar 펼침에서 해당 줄을 체크박스로, 일반 줄은 텍스트 그대로 — 혼합 허용 | 공지 전체를 체크리스트로 강제하지 않는다 |
| 토글 권한 | 두 참가자 모두 (공지 공동 편집과 동일) | 스터디 과제는 서로 체크해 준다 |
| 토글 API | `PATCH /notice/check {line_index, checked}` — 서버가 **해당 줄만** `[]`↔`[x]` 원자 치환 (행 잠금) | 전체 PUT 재전송이면 동시 토글이 서로를 덮어쓴다 |
| 동기화 | 토글 성공 시 WS `chat.notice` 재조회 (기존 채널 재사용) — **시스템 줄 없음** | 체크마다 시스템 줄이면 대화가 오염된다 (등록/내리기만 시스템 줄 유지) |
| 접힌 바 | 체크 항목이 있으면 제목 옆 `n/N` 진행 배지 | 접힌 상태에서도 진행이 보인다 (정보 냄새 — 학습 탭 접기와 동일 문법) |
| 편집 시트 | textarea 유지 + "[] 체크 항목 추가" 버튼(커서 위치에 문법 삽입) + 힌트 한 줄 | 문법을 몰라도 쓸 수 있게 |
| 검증 | PATCH 의 line_index 가 체크 항목 줄이 아니면 422 `not_check_line` | 일반 줄 오염 방지 |
| 위장(excel) | 체크박스는 업무 문서에 자연스러움 — 라벨·플레인 규칙 유지 | 위장 계약 유지 |

기각: 별도 checklist 테이블 — 대화당 1공지·항목 수십 개 규모에 과설계, text
원문이 단일 진실이면 편집(PUT)과 체크(PATCH)가 같은 곳을 본다 / 프론트 전체
PUT 방식 — 동시 토글 유실 / 체크 시스템 줄 — 대화 오염.

### 테스트 계약 (추가분)

- `[] a\n일반\n[x] b` PUT → GET 후 프론트 파싱 기대값, PATCH 토글 → text 의
  해당 줄만 변경 (다른 줄 불변), 동시 PATCH 2건 → 둘 다 반영 (행 잠금)
- 422: line_index 범위 밖·일반 줄 대상 / 403: 친구 해제 후 PATCH
- 접힌 바 진행 배지 `n/N`, 일반 텍스트만 있는 공지는 배지 없음
