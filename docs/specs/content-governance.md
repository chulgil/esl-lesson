# 스펙: 콘텐츠 거버넌스 — 관리자 큐레이션 + 허락 증빙

> 최종 검증: 2026-07-30 (코드 대조 완료)

콘텐츠 등록 권한을 관리자로 일원화하고, 비 CC 영상은 **원저작자 허락 증빙을 남긴 경우에만** 등록되도록 강제한다. 사용자는 올라온 콘텐츠를 **담아서** 학습한다. [content-pipeline.md](content-pipeline.md) 의 콘텐츠 가시성 규칙을 대체한다.

## 배경: 왜 바꾸는가

기존 구조는 회원 누구나 유튜브 URL·수기 스크립트를 등록하면 서비스가 자막을 수집·번역·가공했다. 문제는 두 가지다.

- **책임 귀속**: 자막을 가져오고 번역을 저장하고 학습 항목을 만드는 주체는 서비스 자신이다. 사용자 등록 경로가 있어도 OSP 면책(제102조)보다 직접 이용주체로 평가될 여지가 크다 — 즉 사용자 등록은 방패가 되지 못하면서 코퍼스만 무한정 늘린다.
- **허락 확보 불가**: 사용자가 올린 임의 영상은 권리자 허락을 받을 방법이 없다. 반면 관리자가 큐레이션하면 **개별 허락을 받아 침해 자체를 성립시키지 않을 수 있다** (공정이용 항변은 법정에서 다투는 것이지만, 이용허락은 애초에 침해가 아니다).

## 결정 사항 (2026-07-27, 사용자 결정)

| 항목 | 결정 |
|---|---|
| 콘텐츠 등록 | 관리자 전용. 유튜브 URL·수기 입력 **둘 다** 사용자 경로 제거 |
| 사용자 학습 편입 | **명시적 "내 학습에 담기"** — 담아야 학습 큐·게임에 편입 |
| 기존 개인 콘텐츠 4건 | ~~그대로 유지~~ → **일괄 공용 승격** (2026-07-28 사용자 재결정, 마이그레이션 a6b7c8d9e0f1) — pending 항목을 먼저 승인해 기존 구독자의 학습 재료·기록·담김 상태를 그대로 보존. rejected 는 존중, 라이선스 값은 보존(CC 게이트는 소유자 지시로 우회) |
| 비 CC 영상 등록 | 허락 증빙 입력 시에만 허용 (기존 `allow_non_cc` 불리언 대체) |

## 가시성 규칙 (변경)

```
[기존] 노출 = 공용 콘텐츠의 approved 항목 (전 회원 자동)
            ∪ 내가 구독한 개인 콘텐츠의 non-rejected 항목

[신규] 노출 = 내가 담은(구독) 공용 콘텐츠의 approved 항목
            ∪ 내가 담은 개인 콘텐츠의 non-rejected 항목
```

즉 **두 갈래 모두 구독을 전제**로 바뀐다. `visible_item_clause` 단일 지점만 고치면 학습 큐·복습·게임·푸시가 함께 따라온다 (소비처 7개 파일이 모두 이 함수를 경유).

기존 회원의 큐가 갑자기 비지 않도록, 마이그레이션에서 **모든 기존 회원 × 기존 공용 콘텐츠 구독을 백필**한다.

### 전수 감사 결과 (2026-07-28)

"빼면 모든 사용처에서 제외, 기록은 보존" 보장을 위해 ReviewCard/LearningItem 직접 조회 경로를 전수 감사했다. 판단 기준: **표시·출제·집계에 나오면 안 되는 곳 = `visible_item_clause` 필요, 순수 과거 기록 집계(ReviewLog 기반 XP·스트릭·잔디·업적)는 보존 원칙이라 필터하지 않는다**.

누수로 판정해 고친 경로 (5곳):

| 경로 | 증상 → 조치 |
|---|---|
| GET /study/network 노드 (`api/study.py`) | 구독 해제 단어가 어휘망에 잔존 → 노드 쿼리에 가시성 필터 (카드 보존, 재담기 시 복귀) |
| GET /study/stats 레벨 분자 (`api/study.py`) | 해제 항목 카드가 컬렉션 카운트에 잔존 → 분모(visible)와 같은 규칙 적용 |
| GET /study/items/{id}/insight (`api/study.py`) | 비가시 항목 인사이트 조회·LLM 생성 가능 → 가시성 게이트 404 (LLM 비용 차단 겸) |
| 게임 기본 단어 풀 `load_word_pool` (`services/game/manager.py`) | 해제 콘텐츠의 학습 단어가 테트리스·퀴즈 로얄 풀에 잔존 → learned 쿼리에 가시성 필터 |
| 데일리 퍼즐 답 풀 `daily_puzzle.candidates` | 해제 단어가 데일리·연습 답 풀에 잔존 → per-user 가시성 필터. 단 **이미 시작한 오늘 판은 행에 고정된 정답·뜻 유지** |

이미 필터를 경유해 정상인 곳: 학습 큐(due·신규 도입), 오답 선지 풀, stats due_count·분모, 어휘망 추천(고스트), 원탭 카드 추가, 퀴즈 로얄 뉘앙스, 타자·받아쓰기·어순 문장 풀, 푸시 due_count, 채팅 공유 카드 검색·스냅샷, 내 콘텐츠 상세·항목 제외. 설계상 공용 풀이라 필터하지 않는 곳: 빠른 대전 공용 풀(`load_public_word_pool`), 콘텐츠 선택 대전(개인 콘텐츠는 구독 검사, 공용은 공용 풀의 부분집합). 기록 보존이라 제외: XP·스트릭·잔디·리더보드·업적·퀘스트 진행(ReviewLog/ReviewCard 생성 이력 집계).

## 항목 승인 기본값 (2026-07-30 변경)

추출된 학습 항목의 `review_status` 기본값을 `pending` → **`approved`** 로 전환.
등록이 관리자 전용이 된 뒤로는 영상 선정 자체가 큐레이션이라, 항목별 수동
승인은 "담았는데 카드가 없음"이라는 함정만 만들었다 (2026-07-30 보고 —
TEDx 영상 66개 항목 중 65개가 pending 으로 잠겨 있었음). 부적절한 항목은
백오피스에서 **사후 거절**하며, rejected 는 가시성 규칙이 계속 존중한다.

## 데이터 모델: content_permissions (신규 1:1 테이블)

허락 증빙은 `contents` 에 컬럼을 9개 붙이는 대신 별도 테이블로 분리한다. 대부분의 콘텐츠(CC·수기)는 행이 없고, 법적 증빙이라는 별개 관심사이며, "증빙 있는 콘텐츠" 판정이 존재 여부로 단순해진다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `content_id` | FK unique | 1:1 |
| `rights_holder` | Text | 권리자명 (채널명·법인명) |
| `rights_holder_contact` | Text? | 이메일 등 연락 수단 |
| `granted_at` | Date | 허락받은 날짜 |
| `scope_transcript` | Bool | 자막 복제·서버 저장 |
| `scope_translate` | Bool | 한국어 번역 작성·제공 (제22조 2차적저작물) |
| `scope_derive` | Bool | 학습 항목 추출·게임 소재 변형 |
| `scope_commercial` | Bool | 광고·유료 등 상업적 이용 |
| `evidence` | Text | 증빙 위치 (메일 링크·보관 경로) 또는 요지 |
| `note` | Text? | 조건·기간·해지 등 특약 |
| `recorded_by` | FK users | 기록한 관리자 |

### 범위 검증 규칙

`scope_transcript`, `scope_translate`, `scope_derive` 가 **모두 true 여야** 등록을 허용한다. 파이프라인이 실제로 수행하는 이용이 이 셋이므로, 하나라도 빠지면 그 콘텐츠는 처리 자체가 허락 범위를 벗어난다. 위반 시 `422 permission_scope_insufficient`.

`scope_commercial` 은 등록을 막지 않는다 — 현재 무료 서비스라 당장 필요하지 않지만, 수익화 시 어느 콘텐츠를 빼야 하는지 판별하려면 지금 기록해 두어야 한다.

### CC 게이트와의 관계

```
license == creativeCommon        → 허락 증빙 없이 등록 가능 (CC 자체가 이용허락)
license != creativeCommon 또는 미확인 → content_permissions 필수, 없으면 409 cc_required
```

기존 `allow_non_cc: bool` 오버라이드는 제거한다. 체크박스 하나로 게이트를 뚫으면 분쟁 시 "허락받았다"를 입증할 데이터가 서비스에 남지 않는다.

## 난이도 배지·아는 표현 비율 (2026-08-05)

담기는 되돌릴 수 있어도 "잘못 담아 학습 큐가 무너지는" 비용은 사용자가 진다. 목록에서 **담기 전에** 수준을 보여준다 (proposal/effectiveness-audit-2026-08.md P0-2). 저장 컬럼·마이그레이션 없이 `GET /api/contents` 조회 시 실시간 파생한다.

| 필드 | 산출 | 값 |
|---|---|---|
| `difficulty` | 콘텐츠 항목의 `difficulty_hint` 가중 평균 (basic=0, intermediate=1, advanced=2) **+ 문장 길이 보정** (아래) | 항목 0개면 `null` |
| `known_ratio` | 항목 중 내 `review_cards` 가 이미 있는 항목의 비율 (반올림 정수) | 0~100 / 항목 0개면 `null` |

**문장 길이 보정 (2026-08-10 — P0-2 보류분 착수)**: 추출 힌트에 `basic` 이
사실상 없어(프로드 전 항목 0건) 힌트 평균이 [1.0, 1.4] 로 압축된다 — 힌트만으로는
초급이 절대 안 나와 Easy English 류 초급 회화가 중급으로 오분류됐다 (사용자 보고).
콘텐츠 평균 문장 단어 수(`transcript_segments`, 공백 수+1 근사)를 함께 본다:

- 세그먼트 있음: 평균 >= 1.35 **또는** 문장당 >= 17단어 → `advanced` /
  평균 <= 1.12 **그리고** 문장당 <= 8단어 → `beginner` / 그 외 `intermediate`
- 세그먼트 없음(수기): 기존 힌트-단독 기준 (>= 1.35 / <= 0.6)
- 경계값은 프로드 11개 콘텐츠 실측으로 캘리브레이션 — 초급 회화(3.4~6.9단어/문장,
  힌트 1.00~1.10) vs 강연(15~18단어, 1.25~1.40)이 깨끗이 갈린다

- DB 의 `basic` 은 노출 라벨 `beginner`(초급) 로 맞춘다 — 업적 티어(beginner/intermediate/advanced) 와 같은 어휘를 쓴다.
- 두 값 모두 목록 전체를 `GROUP BY` 한 번으로 집계한다 (콘텐츠당 N+1 금지).
- `known_ratio` 의 분모는 카드에 표시되는 `item_count` 와 동일하다 (사용자가 두 수를 대조할 수 있게).
- 프론트: `/library` 카드에 난이도 배지(초급 green / 중급 blue / 고급 red) + "아는 표현 n%" 칩.

**레벨 필터·맞춤 정렬 (2026-08-10 — proposal/level-fit-library-2026-08.md MVP)**:

- 필터 칩 `[전체][초급][중급][고급]` — 기본 선택 = 내 레벨 (`study_level` 1~2=초급,
  3=중급, 4=고급), 딥링크 `?level=beginner|intermediate|advanced`
- 기본 정렬 = 맞음(fit) 점수 내림차순 — 난이도 거리(같음 2/±1단 1) + 아는 표현
  (60~85% 2 / 40%+ 또는 85%+ 1). fit 4 카드는 "지금 내 수준" 하이라이트
- 레벨 필터 결과 0 = 공급 신호 — 빈 상태 문구가 콘텐츠 요청 폼으로 안내

## 남는 리스크 (이 스펙 범위 밖)

허락을 받아도 **유튜브 이용약관은 별개 계약**이다. 현재 파이프라인은 비공식 자막 API 와 정렬용 `yt-dlp` 오디오 다운로드를 쓰는데, 이는 저작권과 무관하게 ToS 의 다운로드·스크래핑 금지에 걸린다. 근본 해결은 **권리자에게 자막·오디오를 직접 수급**해 유튜브를 경유하지 않는 것이며, 허락 협의 시 함께 요청하는 것을 권장한다. 재생은 계속 공식 임베드를 쓴다.

또한 업로더가 영상 내 음악·인용 클립·게스트 발언의 권리자가 아닐 수 있어, 본인 발화 중심의 강의·토크형 영상을 우선한다.

법률 자문 의뢰서는 [../legal/consult-brief.md](../legal/consult-brief.md) 를 이 모델 기준으로 갱신한다.

## 테스트

- 가시성: 담지 않은 공용 콘텐츠 항목은 학습 큐·게임에 안 나옴 / 담으면 나옴
- 담기: 멱등, `ready` 아닌 콘텐츠 거부, 빼기 후 큐에서 사라짐
- 등록 차단: `POST /api/my/contents` 404 (유튜브·수기 모두)
- retry: 공용 콘텐츠 재시도 거부, 개인 콘텐츠는 허용
- 허락 게이트: CC → 증빙 없이 통과 / 비 CC → 증빙 없으면 409 / 범위 누락 시 422 / 정상 입력 시 저장·조회
- 마이그레이션: 기존 회원 × 공용 콘텐츠 구독 백필
- 난이도 배지: 고급/중급/초급 분포별 라벨, 경계값(1.35·0.6), 항목 0개 → `null`
