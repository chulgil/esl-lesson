# 스펙: 워드 테트리스 (페이즈 2 — 네트워크 영어 게임)

> 최종 수정: 2026-07-11

테트리스 스타일 UI/이펙트의 1:1 대전 타이핑 게임. 단어 브릭이 위에서 내려오고, 플레이어가 해당 단어(또는 뜻)를 빠르게 타이핑해 쳐낸다. 사람 vs 사람(PvP), 사람 vs AI(PvE) 모두 지원.

## 게임 규칙

### 보드/낙하

- 보드: 세로 12칸 스택. 단어 브릭이 일정 간격으로 상단 생성 → 한 칸씩 하강.
- 브릭에는 출제 텍스트 표시. 출제 모드는 매치 설정:

| 모드 | 브릭 표시 | 정답 입력 |
|------|-----------|-----------|
| en (기본) | 영단어 | 그 영단어 타이핑 (철자 훈련) |
| ko2en | 한글 뜻 | 대응 영단어 타이핑 (회상 훈련) |

- 입력 일치 판정: 대소문자 무시, 완전 일치. 보드 내 여러 브릭이 매칭되면 가장 아래(위험한) 브릭 제거.
- 브릭이 바닥에 닿으면 스택으로 굳음. 스택이 천장(12칸) 도달 = KO 패배.
- 시간이 지날수록 낙하 속도/생성 간격 가속 (테트리스 레벨업과 동일 곡선: 30초당 1단계, 10단계 상한).

### 공격/방어 (대전 코어)

| 행동 | 효과 |
|------|------|
| 콤보 (연속 정답, 오타 없이) | 3콤보마다 상대 보드에 garbage 브릭 1개 추가 (즉시 스택에 쌓임) |
| 긴 단어 클리어 (8자 이상) | garbage 1개 |
| garbage 브릭 | 회색 브릭 — 자기 보드의 아무 단어나 하나 클리어해야 함께 소멸 |
| 오타 (Enter 제출 기준) | 콤보 리셋 + 0.3초 입력 잠금 |

### 승패

- 상대 KO / 제한시간 3분 종료 시 점수 우위 / 상대 이탈(10초 재접속 유예 후 몰수승).
- 점수: 클리어 +10 x (1+콤보x0.1) + 단어 길이 보너스. 통계로 WPM/정확도 기록.

### 단어 소스 선택 (2026-07-11 개정)

- **방 만들기(친구 초대)·AI 대전**: 방 생성 시 소재 선택 — [공용 전체] 또는 [내 콘텐츠 선택(다중)]. 선택한 콘텐츠의 word 항목으로 두 플레이어가 대전 (초대받은 친구도 방장 콘텐츠 단어 사용).
- **빠른 대전(랜덤 매칭)**: 공정성을 위해 공용 풀 고정.

### 단어 소스

- 기본 풀: 사용자가 학습한(approved + 카드 존재) word 항목 — **학습과 게임의 선순환**.
- 풀이 40개 미만이면 전역 approved word로 보충. 단어 길이 3-12자 제한.
- 매치 시작 시 서버가 시드 고정 셔플로 100개 큐 생성 (양 플레이어 동일 순서 — 공정성).

## 테트리스식 이펙트 (요구사항: "각종 이펙트 모두 적용")

| 이벤트 | 이펙트 |
|--------|--------|
| 클리어 | 브릭 파열(파티클 4-8개) + 라인 플래시 |
| 콤보 | "COMBO xN" 팝업 확대→소멸, N 커질수록 화면 가장자리 글로우 강화 |
| 4연속 급클리어 (테트리스의 Tetris) | 화면 전체 플래시 + "QUAD!" + 특수 사운드 |
| garbage 공격 발신/수신 | 상대 보드로 날아가는 브릭 궤적 / 수신 측 화면 상단 경고 점멸 |
| 위험 (스택 9칸 이상) | 배경 붉은 펄스 + 심장박동 사운드 |
| KO | 승자: 폭죽 + 브릭 타워 / 패자: 보드 와르르 무너짐 (중력 낙하) |
| 낙하 가속 단계업 | "SPEED UP" 배너 + 배경 괘선 스크롤 가속 |

- 렌더링: Canvas 2D (60fps, requestAnimationFrame). DOM은 입력창/HUD만.
- 사운드: 클리어/콤보/경고/KO 4종 (on/off 토글, 기본 off — 웹 예의).
- 프레임(보드 테두리, 버튼, 로비)은 노트x레고 디자인 시스템 유지 — [ui-design.md](ui-design.md).

## 네트워크 아키텍처

- 전송: WebSocket `wss://<도메인>/ws/game` (FastAPI, 쿠키 JWT 인증).
- 모델: **서버 권위(server-authoritative)** — 낙하 틱, 판정, 점수, 공격 모두 서버 계산. 클라이언트는 입력 전송 + 상태 렌더링만 (치팅 방지).
- 틱: 서버 10Hz 상태 브로드캐스트 (보드 12칸 x 단어 id라 페이로드 소형). 클라이언트는 보간으로 부드럽게.

### 메시지 프로토콜 (JSON)

```
클라이언트 → 서버
  {"t": "queue.join", "mode": "pvp"|"pve", "quiz": "en"|"ko2en", "bot_level": 1-5?}
  {"t": "room.create"} / {"t": "room.join", "code": "ABC123"}   # 친구 초대
  {"t": "input.submit", "text": "resilient", "seq": 42}
  {"t": "ping"}

서버 → 클라이언트
  {"t": "match.found", "match_id": 7, "opponent": {...}, "countdown": 3}
  {"t": "state", "tick": 120, "me": {board, combo, score}, "op": {board, combo, score}}
  {"t": "clear.result", "seq": 42, "ok": true, "word_id": 55, "effects": ["combo3","attack"]}
  {"t": "attack.recv", "count": 1}
  {"t": "match.end", "winner": "me"|"op"|"draw", "stats": {...}}
  {"t": "error", "code": "room_not_found" | ...}
```

- `seq`로 입력-결과 매칭 (지연 중 연타 대응).
- 재접속: match_id + 토큰으로 10초 내 재합류 → 서버가 전체 상태 재전송.

## 매치메이킹

| 방식 | 흐름 |
|------|------|
| PvE | 즉시 시작 — 봇 난이도 1-5 선택 |
| PvP 랜덤 | 대기열 등록 → 상대 발견 시 매칭. 30초 무매칭 → 봇 전환 제안 |
| PvP 친구 | 6자 방 코드 생성/입력 |

동시 매치 상태는 백엔드 인메모리 (단일 프로세스 — [tech-stack.md](../architecture/tech-stack.md) 결정). 서버 재시작 시 진행 중 매치는 abort 처리 후 기록.

## AI 봇 설계

봇 = "가상 타이핑 속도를 가진 플레이어" 시뮬레이션. 서버가 봇 보드를 동일 규칙으로 운영한다.

| 난이도 | 타이핑 속도(WPM) | 정확도 | 반응 지연 |
|--------|------------------|--------|-----------|
| 1 | 15 | 88% | 1.5-3.0s |
| 2 | 25 | 92% | 1.0-2.0s |
| 3 | 35 | 95% | 0.7-1.5s |
| 4 | 50 | 97% | 0.5-1.0s |
| 5 | 70 | 99% | 0.3-0.6s |

- 봇은 가장 아래 브릭부터 처리, `단어길이/WPM` 시간 경과 후 클리어. 오타 확률만큼 콤보 리셋 발생 — 사람다운 리듬.
- 난이도별 승률 목표: 사용자 평균 대비 1=쉬움(승률 80%+) ~ 5=도전(20% 이하).

## 화면 흐름

```
게임 로비 (/game)
 ├─ [빠른 대전(PvP)] [AI 대전(난이도 선택)] [친구 초대(방 코드)]
 ├─ 출제 모드 선택: 영단어 타이핑 / 뜻보고 영단어
 └─ 내 전적: 승/패, 최고 WPM, 최다 콤보

대전 화면
 ├─ 좌: 내 보드(대형) + 입력창(항상 포커스)
 ├─ 우: 상대 보드(소형 미러) + 콤보/점수 HUD
 └─ 종료 → 결과 화면 (통계, 재대결 버튼)
```

## 데이터 저장

- 매치 종료 시 `game_matches` 1행 (모드, 승자, 점수, stats jsonb: WPM/정확도/최다콤보/처리단어수).
- 랭킹(선택 구현): 주간 점수 합산 리더보드 — `game_matches` 집계 쿼리로 충분, 별도 테이블 없음.

## API (REST 보조)

| 메서드/경로 | 설명 |
|-------------|------|
| GET `/api/game/profile` | 내 전적/최고 기록 |
| GET `/api/game/leaderboard` | 주간 리더보드 |
| WS `/ws/game` | 대전 (위 프로토콜) |

## 페이즈 2 구현 순서

1. 싱글 보드 로컬 프로토타입 (낙하/타이핑/이펙트, 서버 없음)
2. PvE: 서버 권위 루프 + 봇
3. PvP: 매칭/방 코드/재접속
4. 전적/리더보드
