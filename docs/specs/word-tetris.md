# 스펙: 워드 테트리스 (네트워크 영어 게임)

> 최종 검증: 2026-07-30 (코드 대조 완료)

테트리스 스타일 UI/이펙트의 1:1 대전 단어 게임. 단어 브릭이 위에서 내려오고, 플레이어가 하단 칩에서 해당 단어(또는 뜻)를 빠르게 탭해 쳐낸다. 사람 vs 사람(PvP), 사람 vs AI(PvE) 모두 지원.

## 게임 규칙

### 보드/낙하

- 보드: 세로 12칸 스택. 단어 브릭이 일정 간격으로 상단 생성 → 한 칸씩 하강.
- **낙하물 테마화** (2026-07-31): 배경뿐 아니라 브릭 몸통·팔레트·텍스트색이 테마 오브젝트로 렌더 — 캔디=젤리(광택), 노트=파스텔 쪽지(접힌 모서리), 레고=스터드 브릭(원색·하드섀도), 헤냥이=고양이 귀 브릭, 학교수업=칠판+칠판지우개(분필 텍스트, 클리어 팝=분필 가루), 학원=갱지 모눈 문제지+답안 칩(채점펜 빨간 세로선·마킹 동그라미, 2026-08-04). 오피스는 노트 보드 폴백(위장 유지 결정). `BoardCanvas` `PALETTES`/`drawBrickBody`/`drawBackground` 3곳이 테마 분기의 전부.
- 브릭에는 출제 텍스트 표시. 출제 모드는 매치 설정:

### 레벨 기반 구간(세그먼트) 방향 (2026-07-11 개정 — 섞지 않음)

방향을 브릭마다 랜덤으로 섞지 않는다. **속도 레벨 구간마다 출제 방향이 하나로 고정**되고, 레벨이 오르며 방향이 번갈아 바뀐다. 브릭은 스폰 시점의 방향을 유지하므로 구간 전환 순간에만 두 방향이 잠깐 공존한다.

| 방향 | 브릭 표시 | 정답 입력 | 훈련 |
|------|-----------|-----------|------|
| en2ko (영→한) | 영단어 | 하단 한글 뜻 칩 **탭** | 뜻 회상 |
| ko2en (한→영) | 한글 뜻 | 하단 영단어 칩 **탭** | 회상 |

입력 방식은 **전 레벨 칩 탭 하나**다 (2026-08-03 사용자 기획 — 타이핑 구간 폐지). 낙하 압박 + IME 전환이 겹치면 학습이 아니라 조작 훈련이 된다. `input_mode` 필드는 프로토콜 호환을 위해 남기되 값은 항상 `tap` 이며, 타이핑 재도입은 `input_mode_for_level` 한 곳만 바꾸면 된다.

구간 배치 (speed_level 기준, 30초당 1레벨 — 2레벨마다 교대):

| 레벨 | 구간 방향 |
|------|-----------|
| 0-1 (0-60s) | en2ko — 영어 보고 한글 탭 (쉬운 회상) |
| 2-3 (60-120s) | ko2en — 한글 보고 영어 탭 (생산 회상) |
| 4-5 (120-180s) | en2ko — 고속 탭 |
| 6-7 (180-240s) | ko2en — 고속 탭 |
| 8-9 (240-300s) | en2ko — 최고속 탭 |
| 10 (300s~) | ko2en — 최고속 탭 (`MAX_SPEED_LEVEL=10` 상한, 이후 레벨 고정) |

6레벨 이후에도 2단계마다 계속 교대한다 — 표를 "6+ 고정 ko2en" 으로 오독하지
말 것 (`direction_for_level`, `services/game/engine.py:41-44` 정본). 단, 매치
제한시간이 3분(`MATCH_SECONDS=180`)이라 통상 매치에서는 레벨 6 부근에서 종료된다.

- 구간이 바뀌면 화면에 방향 배너("영어 → 한글" / "한글 → 영어")를 띄운다.
- **탭 칩 = 학습카드式 보기 그룹 (2026-08-10 개정)**: 가장 위험한(착지 우선, 아래쪽 우선) 브릭 3개에 **3+3+2 그룹, 총 최대 8개**를 하단에 표시. 각 그룹은 그 브릭의 정답 1 + 같은 언어 오답 — 학습카드 선다처럼 "지금 벽돌의 보기"가 한 묶음으로 보인다. 첫 그룹(가장 급한 벽돌)은 크게·파란 테두리, 뒤 그룹은 작게. 4번째 이후 브릭의 보기는 앞 브릭을 지우면 나온다.
- **오답 샘플링**: **이 매치의 단어 풀**에서 먼저 뽑고(실제 단어라 더 학습적), 모자라면 고정 오답 목록으로 폴백. 다른 보드 브릭의 정답은 오답으로 쓰지 않는다(오답인 줄 알았는데 클리어되는 혼란 방지). 브릭별 고정 시드 셔플로 매 틱 흔들리지 않는다. 프로토콜은 `chip_groups`(그룹) + `chips`(평탄화, 하위호환) 병행.
- **정답 노출 규칙**: 양방향 모두 선다형이므로 정답 칩 노출이 안전하다.
- 브릭이 en/ko 를 모두 보유(word_queue = (id, en, ko))하고, 스폰 시 구간 방향으로 표시/정답을 결정한다.

- 입력 일치 판정: 대소문자 무시, 완전 일치. 보드 내 여러 브릭이 매칭되면 가장 아래(위험한) 브릭 제거.
- 브릭이 바닥에 닿으면 스택으로 굳음. 스택이 천장(12칸) 도달 = KO 패배.
- 클리어/폭탄으로 스택 중간이 비면 위 브릭이 내려앉는다(압축) — 공중부양·겹침 금지 (2026-07-13).
- 서버 틱은 벽시계 dt 에 상한 0.3s(MAX_TICK_SECONDS) — 서버 스톨/순단 후 순간이동 대신 잠깐 느려졌다 회복 (2026-07-13).
- 시간이 지날수록 낙하 속도/생성 간격 가속 (테트리스 레벨업과 동일 곡선: 30초당 1단계, 10단계 상한).

| 행동 | 효과 |
|------|------|
| 콤보 (연속 정답, 오타 없이) | 3콤보마다 상대 보드에 garbage 브릭 1개 추가 (즉시 스택에 쌓임) |

| 오타 (Enter 제출 기준) | 콤보 리셋 + 0.3초 입력 잠금 |

### 승패

- 상대 KO / 제한시간 3분 종료 시 점수 우위 / 상대 이탈(10초 재접속 유예 후 몰수승).
- **PvE(봇전) 이탈은 몰수패가 아니라 기록 제외(aborted)** — 혼자 연습 중
  나간 판이 전적에 패로 쌓이는 문제 수정 (2026-07-14)
- 점수: 클리어 +10 x (1+콤보x0.1) + 단어 길이 보너스. 통계로 WPM/정확도 기록.
- 결과 화면에 **나:상대 최종 점수 비교** 명시 — 승패 근거가 보이게 (2026-07-14)

### 단어 소스 선택 (2026-07-11 개정)

- **방 만들기(친구 초대)·AI 대전**: 방 생성 시 소재 선택 — [공용 전체] 또는 [내 콘텐츠 선택(다중)]. 선택한 콘텐츠의 word 항목으로 두 플레이어가 대전 (초대받은 친구도 방장 콘텐츠 단어 사용).
- **빠른 대전(랜덤 매칭)**: 공정성을 위해 공용 풀 고정.

### 단어 소스

- 기본 풀: 사용자가 학습한(approved + 카드 존재) word 항목 — **학습과 게임의 선순환**.
- 풀이 40개 미만이면 전역 approved word로 보충. 단어 길이 3-12자 제한.
- 매치 시작 시 서버가 시드 고정 셔플로 100개 큐 생성 (양 플레이어 동일 순서 — 공정성).
- **복습 우선 출제 (공유 원칙: 복습 우선 편입 — P0-A, 2026-08-10)**: due 도래
  카드 + 최근 7일 오답 카드의 항목이 셔플 순서를 유지한 채 큐 앞으로 온다
  (`priority_item_ids` — PvP 는 두 플레이어 합집합이라 동일 큐 = 공정성 유지,
  조회 실패 시 빈 셋 폴백). 게임 한 판이 곧 복습이 된다 (effectiveness-audit 4차).
- **노출 방식(테트리스 고유)**: 우선 항목은 스폰 큐 **앞쪽에 고정 배치**되어
  먼저 낙하한다 — 재셔플 없이 셔플 순서만 유지한 채 앞으로 당김
  (`build_word_queue`, `services/game/engine.py`). 게임마다 노출 방식이 다르니
  다른 게임의 규칙을 그대로 가정하지 말 것 (빙고·퀴즈로얄은 재셔플로 분산).
- **종료 시 복습 회수**: 못 지운(보드에 남은) 브릭의 단어를 `match.review{items}`
  개인 메시지로 전송 — 결과 화면 ReviewPanel 원탭 학습 추가 (다른 게임 4종과 동일 패턴).

## 아이템 시스템 (파워업, 2026-07-11 추가)

전략성과 재미를 위한 파워업. 서버 권위로 적용(치팅 방지). 인벤토리 최대 3개.

### 획득 (둘 다)

- **콤보 보상**: 5콤보 달성마다 랜덤 아이템 1개
- **아이템 브릭**: 가끔(약 7스폰당 1회) 반짝이는 별(★) 브릭이 낙하 → 클리어 시 랜덤 아이템 1개
  - ★ 브릭도 **문제 텍스트를 표시**하고 정답 칩이 내려온다 (★만 표시하면 무엇을 입력할지 알 수 없어 클리어 불가 — 2026-07-13 개정)

### 아이템 4종

| 아이템 | 효과 | 서버 처리 |
|--------|------|-----------|
| 시간 정지 (freeze) | 3초간 내 보드의 낙하/생성 정지 | `frozen_until = elapsed + 3` |
| 힌트 (hint) | 가장 위험한 브릭의 정답(뜻/철자)을 1.5초 표시 | 요청자에게만 정답 1건 전송(item.hint) |
| 폭탄 (bomb) | 내 보드의 방해블록(garbage) 전체 제거 | garbage 브릭 일괄 제거 |
| 방어막 (shield) | 다음에 들어올 상대 공격 1회 무효화 | `shield_count += 1`, add_garbage 시 소모 |

### 사용 프로토콜

```
클라이언트 → 서버:  {"t": "item.use", "item": "freeze"|"hint"|"bomb"|"shield"}
서버 → 클라이언트:  {"t": "item.result", "item": "...", "ok": true, "hint_answer": "..."?}
                   state 의 me.items / me.frozen / me.shield 로 인벤토리·상태 반영
```

- 인벤토리에 해당 아이템이 없으면 무시(ok=false).
- 힌트는 요청자에게만 정답을 보내 상대가 못 보게 한다.

## 테트리스식 이펙트 (요구사항: "각종 이펙트 모두 적용")

| 이벤트 | 이펙트 |
|--------|--------|
| 클리어 | 브릭 파열(파티클 4-8개) + 라인 플래시 |
| 콤보 | "COMBO xN" 팝업 확대→소멸, N 커질수록 화면 가장자리 글로우 강화 |
| 4연속 급클리어 (테트리스의 Tetris) | 화면 전체 플래시 + "QUAD!" + 특수 사운드 |
| garbage 공격 발신/수신 | 상대 보드로 날아가는 브릭 궤적 / 수신 측 화면 상단 경고 점멸 |
| 위험 (스택 9칸 이상) | 배경 붉은 펄스 + 심장박동 사운드 |
| KO | 승자: 폭죽 + 브릭 타워 / 패자: 보드 와르르 무너짐 (중력 낙하) |
| 낙하 가속 단계업 | "SPEED UP" 배너 + 배경 괘선 스크롤 가속 |

### 비주얼 개정 (2026-07-13 — 캔디 컨셉)

- 브릭 = 글로시 파스텔 캔디 (광택 하이라이트 + 젤리 두께감), 캔버스 폰트는 손글씨(--font-hand)
- garbage = **×_× 얼굴의 회색 젤리** (기존 `###` 표기 폐지 — 정체불명 혼란)
- 클리어 = 버블 팝 (확장 링 + 방사형 방울 파티클 레이어링)
- 보드 배경 = 전역 테마(설정 > 테마: 노트/캔디/레고)를 따름 — [ui-design.md](ui-design.md)
- 룰 전달 장치: 오답 셰이크 + "콤보 리셋" 표시, 첫 garbage 수신 1회 설명 토스트,
  구간 전환 대형 배너, 아이템 획득 토스트, 아이템 버튼 라벨에 효과 내장("3초 멈춤" 등)

- 렌더링: Canvas 2D (60fps, requestAnimationFrame). DOM은 입력창/HUD만.
- 사운드: 클리어/콤보/경고/KO 4종 (on/off 토글, 기본 off — 웹 예의).
- 프레임(보드 테두리, 버튼, 로비)은 노트x레고 디자인 시스템 유지 — [ui-design.md](ui-design.md).

## 네트워크 아키텍처

- 전송: WebSocket `wss://<도메인>/ws/game` (FastAPI, 쿠키 JWT 인증).
- 모델: **서버 권위(server-authoritative)** — 낙하 틱, 판정, 점수, 공격 모두 서버 계산. 클라이언트는 입력 전송 + 상태 렌더링만 (치팅 방지).
- 틱: 서버 10Hz 상태 브로드캐스트 (보드 12칸 x 단어 id라 페이로드 소형). 클라이언트는 보간으로 부드럽게.

### 메시지 프로토콜 (JSON)

```
클라이언트 → 서버
  {"t": "queue.join", "mode": "pvp"|"pve", "quiz": "en"|"ko2en", "bot_level": 1-5?}
  {"t": "room.create"} / {"t": "room.join", "code": "ABC123"}   # 친구 초대
  {"t": "input.submit", "text": "resilient", "seq": 42}
  {"t": "ping"}

서버 → 클라이언트
  {"t": "match.found", "match_id": 7, "opponent": {...}, "countdown": 3}
  {"t": "state", "tick": 120, "me": {board, combo, score}, "op": {board, combo, score}}
  {"t": "clear.result", "seq": 42, "ok": true, "word_id": 55, "effects": ["combo3","attack"]}
  {"t": "attack.recv", "count": 1}
  {"t": "match.end", "winner": "me"|"op"|"draw", "stats": {...}}
  {"t": "error", "code": "room_not_found" | ...}
```

- `seq`로 입력-결과 매칭 (지연 중 연타 대응).
- 재접속: match_id + 토큰으로 10초 내 재합류 → 서버가 전체 상태 재전송.
- 위 목록 외 보조 메시지: `queue.waiting`, `room.created`, `item.gained`,
  `iv.invited`(친구 초대 — `services/game/invites.py`). `state` 페이로드의 보드
  필드 전체 정의는 `frontend/src/lib/game-ws.ts` 의 `BoardState` 타입이 정본
  (chips/direction/input_mode/frozen/shield/items/ko 등 포함).

## 매치메이킹

| 방식 | 흐름 |
|------|------|
| PvE | 즉시 시작 — 봇 난이도 1-5 선택 |
| PvP 랜덤 | 대기열 등록 → 상대 발견 시 매칭. **P2 후보(미구현)**: 30초 무매칭 → 봇 전환 제안 |
| PvP 친구 | 6자 방 코드 생성/입력 |

동시 매치 상태는 백엔드 인메모리 (단일 프로세스 — [tech-stack.md](../architecture/tech-stack.md) 결정). 서버 재시작 시 진행 중 매치는 abort 처리 후 기록.

## AI 봇 설계

봇 = "가상 타이핑 속도를 가진 플레이어" 시뮬레이션. 서버가 봇 보드를 동일 규칙으로 운영한다.

| 난이도 | 타이핑 속도(WPM) | 정확도 | 반응 지연 |
|--------|------------------|--------|-----------|
| 1 | 15 | 88% | 1.5-3.0s |
| 2 | 25 | 92% | 1.0-2.0s |
| 3 | 35 | 95% | 0.7-1.5s |
| 4 | 50 | 97% | 0.5-1.0s |
| 5 | 70 | 99% | 0.3-0.6s |

- 봇은 가장 아래 브릭부터 처리, `단어길이/WPM` 시간 경과 후 클리어. 오타 확률만큼 콤보 리셋 발생 — 사람다운 리듬.
- 난이도별 승률 목표: 사용자 평균 대비 1=쉬움(승률 80%+) ~ 5=도전(20% 이하).

### 리텐션 (P3 — 2026-07-13 구현)

- 로비: **내 전적**(승/패·최고 점수·최다 콤보·최고 WPM) + **주간 리더보드**(최근 7일 합산 top 5)
- 결과 화면: 이번 매치가 개인 기록(score/max_combo/wpm)을 경신하면 `match.end` 의
  `records` 로 수신 → **"○○ 경신!" 배지** (저장 전 과거 기록과 비교 — 첫 판 인플레 방지)
- 재대결: PvE 는 같은 설정(난이도·소재)으로 **즉시 한 판 더**, PvP 는 로비 복귀 (reload 제거)

## 화면 흐름

```
게임 로비 (/game)
 ├─ [빠른 대전(PvP)] [AI 대전(난이도 선택)] [친구 초대(방 코드)]
 ├─ 소재 선택: 내 콘텐츠(미선택 시 공용)

대전 화면
 ├─ 데스크톱 — 좌: 내 보드(대형) + 보기 칩 바(하단 고정) / 우: 상대 보드(소형 미러) + 콤보/점수 HUD
 ├─ 모바일 — 내 보드가 화면 전체, 상대 보드는 내 보드 우상단 반투명 PiP 미니창
 │   (상단 고정 스트립 폐지 2026-08-10 — 상대 화면이 위를 차지해 내 보드가 작아지는 문제)
 └─ 종료 → 결과 화면 (통계, 재대결 버튼)
```

## 데이터 저장

- 매치 종료 시 `game_matches` 1행 (모드, 승자, 점수, stats jsonb: WPM/정확도/최다콤보/처리단어수).
- 랭킹(선택 구현): 주간 점수 합산 리더보드 — `game_matches` 집계 쿼리로 충분, 별도 테이블 없음.
