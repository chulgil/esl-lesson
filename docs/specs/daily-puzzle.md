# 데일리 단어 퍼즐

> 하루 한 단어(전원 동일) 워들 — "몇 번 만에 맞혔나" 공유가 리텐션 훅. 게임 허브 진입.

| 항목 | 값 |
|---|---|
| 단어 선택 | 승인 단어(4~8자 순수 알파벳) 중 **랑데부 해싱**(날짜+단어) — 풀 증가에도 답 안정 |
| 진행 저장 | daily_puzzle_plays (user_id, day UNIQUE) — 첫 추측 시 정답을 행에 고정 |
| 채점 | 서버 — 표준 워들 규칙(중복 글자는 남은 개수만 노랑). 정답은 종료 시에만 공개 + 뜻 표시(학습 모먼트) |
| API | GET /api/game/puzzle, POST /api/game/puzzle/guess (6회 제한, 422/409 가드) |
| 뜻 힌트 | `hint_ko` — **2번 시도부터** 응답에 포함 (HINT_AFTER_TRIES), 정답 단어는 계속 비공개. UI 는 버튼 탭 시 공개 |

XP·리더보드 미연동 (의도) — 판이 아니라 데일리 습관 장치.

## 연습 모드 (2026-07-16, 사용자 피드백: 하루 1판은 가혹·틀리면 할 게 없음)

- **데일리 1판은 유지** (공유·습관 훅 보존) — 끝난 뒤 [연습으로 한 판 더]로
  무제한 연습. 기록·공유·저장 전부 없음, 결과 패널에서 [한 판 더] 반복
- API: GET `/api/game/puzzle/practice` → `{token, length, hint_ko, max_tries}`,
  POST `/api/game/puzzle/practice/guess` `{token, word, final}` → `{marks, correct,
  answer?}` — **무상태**: 정답은 HMAC 서명 토큰(jwt_secret)으로 왕복, DB 미사용
- 연습 단어는 오늘의 데일리 단어 제외(스포일 방지), 랜덤 선택
- 힌트: hint_ko 를 시작 응답에 내리고 클라이언트가 2번 시도 후 버튼 노출
  (연습은 무보상이라 클라 게이트로 충분)
- 거절: 데일리 초기화(같은 단어 재도전) — 정답이 이미 공개돼 무의미하고
  "몇 번 만에 성공" 공유의 신뢰를 깨뜨림

## UX 개편 (2026-07-16, 사용자 피드백: 방법 인지 어려움·UI 작음·이펙트/힌트 없음)

- **입력**: 텍스트 인풋 제거 → 워들 표준 — 현재 행 타일에 직접 타이핑 +
  화면 QWERTY 키보드(시도한 글자를 g/y/x 색으로 표시, 물리 키보드 병행)
- **시인성**: 타일 aspect-square 가변(행 폭 기준, 기존 44px 고정 대비 확대),
  미포함(x) 타일은 진한 잉크색(bg-ink/50 + text-paper) — 회색 저대비 교정
- **이펙트**: 채점 시 타일 뒤집기(tile-flip, 250ms 스태거), 정답 행 순차
  바운스(tile-bounce), 입력 거부 시 행 흔들림(miss-shake), 글자 입력 팝(word-pop)
- **게임 방법**: 첫 방문 자동 모달(localStorage `esl:puzzle:howto-seen`) —
  색 규칙을 예시 타일 3줄로 시각 설명, 헤더 [게임 방법] 버튼으로 재열람
- **플레이 중 `body.game-focus`** — 다른 게임과 동일하게 탭바·마스코트 숨김
  (모바일에서 보드+키보드 한 화면)
