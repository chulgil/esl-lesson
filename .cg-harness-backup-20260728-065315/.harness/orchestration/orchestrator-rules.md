# Orchestrator Rules — 멀티에이전트 워커 운영 규칙

> 이 프로젝트에서 Claude Code 세션이 **워커 디스패치 오케스트레이터**로 동작할 때
> 지키는 규칙. cg-harness *개발*이 아니라, 생성된 프로젝트의 **워커 런타임** 규칙이다.
> 세션 시작 시 자체 점검 대상이며, 위반 시 즉시 사용자에게 알리고 중단한다.

---

## 1. 실행 환경 (INV8 — 인터랙티브 전용)

워커 오케스트레이터는 **인터랙티브 Claude Code 세션에서만** 실행한다. 세션 시작 시 자체 점검:

- 시스템 프롬프트에 `# Background Session` 블록이 보이거나
- 백그라운드 harness 환경변수(`$CLAUDE_JOB_DIR` 등)가 설정돼 있거나
- worktree 격리가 강제되는 환경이면

→ 즉시 거부하고 "인터랙티브 세션에서 다시 시작해주세요" 안내.

**근거**: 백그라운드 harness 는 worktree 진입을 강제하므로 본체 `.harness/` 경로에
직접 쓸 수 없고, 워커 디스패치의 file-as-memory 원칙(결과를 평문 파일로 보존,
다른 워커가 본체를 읽음)과 충돌한다. **worktree/백그라운드 세션 금지.**

---

## 2. 운영 원칙 (Operating Principles — 카파시 4원칙 매핑)

워커 호출 전후로 항상 적용. 상세는 `golden-principles.md` #3·#5·#9·#12 참조.

| 원칙 | 적용 |
|------|------|
| 외과수술식 변경 (#12) | 요청 범위만. 무관 코드·포맷 비접촉 |
| 작은 단위 (#5) | 한 워커 = 한 책임. 거대 brief 금지 |
| 설계 후 구현 (#9) | 복잡 작업은 routing.md decision tree 로 워커 선택 후 |
| 증거 기반 완료 (#10) | 워커 결과는 검증 후 채택. "성공했다는데" 신뢰 금지 |

오케스트레이터의 **내부 추론**은 워커 호출이 아니다(승인 불필요). 별도 워커를 호출해
산출물을 `result.md` 로 받는 것만 승인 대상(approval-policy.md).

---

## 3. 작업 재진입 프로토콜 (기존 작업에 다시 들어갈 때)

이미 진행 중이던 작업을 다시 만질 때(특히 맥락 0인 새 세션) 적용. 끝난 작업이라도
콜드 세션이 맨손으로 시작하지 않게 한다.

**1단계 — 재정박(re-anchor, 필수)**: 어떤 액션(편집·워커 호출) 전에도 먼저 읽는다 —
작업 상태(goal·status·승인된 워커) → 현재 컨텍스트 스냅샷 → 최근 로그(특히 마지막
`[WORKER_CALL]`/`[VERIFICATION]`) → 관련 `brief.md`·`result.md`. **읽기 전 행동 금지.**

**2단계 — 분기 판단** (result.md 유무만으로 판단하지 말 것):

- **초기 실행** — brief·result 모두 없음 → 정상 라이프사이클
- **응답 대기/지연** — `[WORKER_CALL]` 만 있고 result.md 없음 → hang 인지 늦은 응답인지 확인
- **부분 재실행** — 특정 워커 result 만 미흡 → 그 워커만 재호출. 다른 결과 보존
- **기존 결과 개선** — 이전 result.md 는 덮지 말고 버전 보존, 채택본을 컨텍스트에 명시
- **새 입력** — 입력이 바뀌면 이전 산출물 보존하고 새 result 로. `target_repo`/`write_scope`
  가 바뀌면 기존 승인 무효 — 새 승인 없이 외부 쓰기 금지

**3단계 — 에러 후 진행(워커 실패·hang·상충)**:

- 실패/타임아웃 → **1회 재시도**. 재실패 시 누락을 `[ERROR]` 로그에 명시하고 가능한 부분만 진행
- 결과 상충(병렬·재실행 간) → 삭제 금지. 양쪽 출처 병기, 권위/사실검증으로 해소,
  `[DECISION]` 기록 (routing.md Fan-in 규칙과 동일)

재진입 시에도 승인 게이트·외부 쓰기 4조건은 그대로 유효.

---

## 4. 자산 수정 후 자가 점검

`.cg/backends.json`·`routing.md`·`templates/*` 등 멀티에이전트 자산을 수정·검증한 뒤에는
전면 재감사 대신 다음만 돌린다:

```bash
cg orchestrate validate --strict   # 내부 일관성 점검 (INV1·3·9·11·12)
```

통과해야 커밋. 깨지면 고치거나, 의도된 변경이면 `system-invariants.md` 를 함께 갱신.
